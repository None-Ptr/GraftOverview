## 8. 已知取舍与偏差（诚实记录）

1. **幽灵连接线未逐条虚线**：mind-elixir 不暴露「某条分支线」的属性；幽灵节点本身为 1.5px 虚线 amber，视觉可区分，但连接线沿用默认实线。
2. **采纳后不重算覆盖率**：遵循 §6.5「覆盖率来自 `ComparisonResult.stats`，不重新计算分数」；采纳会减少活动建议并清除对应幽灵，但顶部覆盖率数字保持本次对比结果。
3. **`src/lib/compare/apply.ts` 归属**：§6.5 与 §7.3 冲突，按编排裁决归 A4（A3 不触碰）。
4. **未对接真实模型**：E2E 与集成测试使用本地 mock 的 OpenAI 兼容响应；真实服务商的浏览器 CORS 与模型差异未在本次自动化中验证（设置页已给诊断清单与 Ollama 兜底）。
5. **仅测 Chromium**：未在 Firefox/WebKit/真实移动设备上跑 E2E；布局按 CSS 断点验证。
6. **新增编排设施**（非契约变更）：`$lib/components`、`$lib/content` 别名；`workspaceStore.setTargetTitle` 与 `replaceMap(map,{markStale})`；`state/history.svelte.ts` 响应式历史。
7. **`apply.ts` 的撤销**：采纳/忽略的撤销通过 5 秒 toast 的「撤销」完成；画布外部变更会重置 A1 的内存撤销栈，故 `Ctrl+Z` 不追溯采纳操作。

## 9. 结论

v0.1.0 达到发布门槛：类型、静态检查、233 个单测、57 个 E2E（浅/深色 a11y、6 断点、完整闭环、共享导入、分段与分支对比、按钮布局、多工作区、模板包、只读分享页、画布拖动与自适应、token 预估与复用、节点定位、目标画布编辑）、性能预算与设计系统门禁全部通过。已知取舍均已记录，无遗留阻断项。

## 12. v0.2 已知取舍

1. **分段合并后不再次截断到 60 条**：每段响应仍按 §4.5 截断到 60，但跨分支合并的结果保留全部（避免丢真实缺口）；UI 分组滚动承载。

3. **分支级对比的目标根不计为缺口**：分段/分支时该子树根作为序列化根（depth 0），模型通常不把它报为缺口，只报其子节点。
4. **续跑只在同一会话内有效**：已完成分支保存在内存，刷新页面后需重新开始（未做持久化续跑）。
5. **未对接真实模型**：分段/分支/校验均为 mock 驱动的自动化验证；真实服务商的分支数与会话限制需实测。

## 13. 缺陷修复：目标体系导入后画布不更新

**症状**：选择模板「算法与数据结构」后，目标出现在右侧面板，但画布保持只有根节点；空状态「从目标生成初稿」打开的是 AI 生成弹窗而不是模板选择。

**根因（两处，已证实）**：
1. `App.handleAction('generate')` 把「从目标生成初稿」错误路由到 `ui.targetGenerateOpen`（AI 生成目标），而不是模板选择 + 草稿复制。
2. `TargetPickerDialog.choose()` 只调用 `workspaceStore.setTarget()`，从不写 `Workspace.map`，因此没有任何「目标 → 画布」的路径。

**修复**：
- 新增 `src/lib/map/draft.ts` `targetAsDraftMap()`（深拷贝、全新 id、保留 note）。
- 空状态「从目标生成初稿」：有目标→直接复制为草稿；无目标→打开模板选择并标记草稿意图，选中后复制。
- 模板选择时，若画布为空（根节点无子节点）或带草稿意图，则同时把模板复制为画布草稿；画布非空时只设置目标，不覆盖用户的导图。
- 取消选择/改走 AI 或大纲路径时清除草稿意图。

**回归**：`tests/e2e/draft.spec.ts` 两条用例（空状态「从目标生成初稿」、空画布直接导入模板）先红后绿；`src/lib/map/draft.test.ts` 覆盖深拷贝与 id 重分配。

**说明**：目标体系默认只进入右侧面板；画布是你的导图。空画布导入模板会自动生成初稿，之后删掉不会的即可；画布非空时请用「从目标生成初稿」显式覆盖。

## 14. 缺陷修复：主按钮图标换行 / 文字被截断

**症状**：顶栏「开始对比 →」的箭头被挤到第二行，并被按钮固定 36px 高度裁掉；按钮宽度只够文字（78px）。

**根因**：`Button.svelte` 把整个 `children` 片段包进单个 `.label`（`display:inline-block; overflow:hidden`）。图标 `<svg>` 是 `display:block`，在非 flex 的 `.label` 内另起一行，被固定高度裁切；且块级子元素不增加按钮内在宽度，图标宽度未计入。

**修复**：`.label` 改为 `inline-flex` 行内布局（`align-items:center`、`gap`、`min-width:0`、`overflow:hidden`），图标与文字同一行并计入宽度（按钮 78 → 100px）；内部文字 `span` 用 `text-overflow:ellipsis` 优雅截断。

**回归**：`tests/e2e/layout.spec.ts` 断言文字与图标在同一行、图标位于文字右侧、不溢出按钮。临时回退 CSS 时该测试报错（上下差 15px），恢复修复后通过。

## 18. 画布拖动（左键平移）

**问题**：导图默认可编辑（`editable: true`）时，mind-elixir 把左键拖拽空白处用于框选，只有右键拖拽或 `Space + 左键` 才能平移画布，用户直观感受是「导图拖不动」。

**修复**：`MapCanvas.svelte` 设置 `mouseSelectionButton: 2`，把框选改到右键拖拽，左键拖拽空白处即平移。

**行为约定**：

| 手势 | 结果 |
|---|---|
| 左键拖拽空白 | 平移画布 |
| 左键拖拽节点 | 移动节点（重新挂载到目标节点下，可撤销） |
| 右键拖拽空白 | 框选 |
| `Space + 左键` 拖拽 | 平移画布（保留原生方式） |
| 滚轮 / 双指 | 平移（`Ctrl/⌘ + 滚轮` 缩放） |

**回归**：`tests/e2e/canvas-drag.spec.ts`
- 左键拖拽空白后 `.map-canvas` 的 `transform` 发生变化；

## 19. 自适应缩放（导图未适配画布）

**问题**：打开大图或导入模板后，导图仍停在 100%，节点超出画布被裁切，右侧/下方大量空白。

**根因（实测）**：

1. `init()` 回调里立即调用 `scaleFit()`。此时节点尚未完成布局，测到的场景尺寸不可靠，缩放保持 1（100%）。实测 73 节点时内容高 3536px、容器仅 630px。
2. 只有组件挂载时拟合一次。之后通过「从目标生成初稿」「导入模板/工程」「切换工作区」整体换图时，没有任何重新拟合的路径，仍沿用旧缩放。

**修复**：

- 初始拟合改到 `requestAnimationFrame` 中执行，等布局完成后再测量；
- 新增 `ui.fitRequest` 信号（`ui.requestFit()`），`MapCanvas` 消费后在下一帧执行 `scaleFit()`；
- 在整体换图的路径上发出信号：从目标生成初稿（App / 模板选择器）、导入工程、切换/新建/删除工作区、重置工作区；
- 采纳建议、忽略缺口等增量修改不发信号，避免打断当前视角；
- 分享页只读画布同步改为下一帧拟合。

**回归**：`tests/e2e/fit.spec.ts`
- 24 分支（73 节点）的大图加载后：缩放 < 100%，内容包围盒完全落在画布内；
- 空画布导入「算法与数据结构」后：内容包围盒落在画布内（实测 20%）。

修复前同样的探针结果为 `scale(1)`、内容高 3536px，`fits: false`。

## 20. 画布铺满（`.map-container` 未填满画布列）

**问题**：`.map-container` 固定为 `70vh`（移动端 `62vh`），外层 `.canvas` 还有 `40px/24px` 内边距，导致画布列上下留白、可平移/可点击的导图表面只有一部分高度（实测容器 844px 而导图表面 652px）。

**回归**：`tests/e2e/fit.spec.ts`

## 21. Token 预估与省 token 机制

**目标**：让用户在与模型交互前就看到大概消耗，避免「不敢点」；同时默认减少无效调用。

**预估展示位置**（均按真实请求计算，不是拍脑袋数字）：

| 入口 | 展示内容 |
|---|---|
| 顶栏「开始对比」左侧 | `≈1.2k tokens`；结果已是最新时显示「已是最新 · 0 tokens」 |
| 目标生成弹窗底部（按钮左侧） | `预计 ≈3.4k tokens · 1 次请求` |
| 分支选择弹窗 | 整图分段对比的总预估与请求次数 |
| 设置「测试连接」左侧 | `≈36 tokens` |

**计算方法**：`src/lib/llm/estimate.ts` 复用 `planChunks` + `serializeTrees` + 真实 system/user Prompt 估算输入；输出按目标节点数估算（对比约 32 tokens/节点，生成假设 100 节点），并以 `maxTokens × 请求数` 封顶。token 估算用 CJK≈1 token/字、其他≈3.6 字符/token 的保守启发式（`src/lib/llm/tokens.ts`），无需引入 tokenizer。

**省 token 机制**：

1. **结果复用（自动，默认开启）**：地图签名、目标签名、当前模型与 host 均未变化时，点「开始对比」直接复用上次结果并提示「内容未变化，已复用上次结果，未调用模型」；提示条提供「仍然重新对比」以便强制刷新。
2. **省 token 模式（可选）**：设置中开启后，对比请求不再发送目标备注（`note`），只按标题比对。估算会同步下降，实际请求体已由 E2E 验证不含备注。
3. **弹窗底部固定**：目标生成与模型设置的操作区移入 Dialog footer，预估与按钮始终可见，不会被滚动的表单挤出视口。

**验证**：

- 单测：CJK/拉丁估算、消息开销、格式化；对比预估的 chunk 数、scope、compact 降幅、maxTokens 封顶、generation 预估。
- E2E：顶栏显示预估；连续点击两次「开始对比」只产生首次请求（含一次 JSON 修复），第二次提示复用；开启省 token 模式后请求体不含目标备注。
- 全量：`check` 0/0、`lint` 通过、218 单测、41 E2E 全绿。

**已知取舍**：预估是启发式，与供应商真实计费存在 ±10–20% 偏差；对比输出量在拿到模型响应前无法精确预知，因此按节点数估算并在悬停说明中给出上限。

## 22. 目标节点定位失效

**现象**：目标面板点击节点或「在画布中定位」没有反应，画布既不选中也不移动。

**根因（实测）**：定位请求只走 `locateTarget()`（幽灵优先、其次 matches）。以下三种情况都会返回 null，且没有任何反馈：

1. **还没做过对比** —— `comparison === null`，所有目标节点都定位不到（最常见）；
2. 对比结果里既没有 match 也没有 gap 的目标节点（例如目标根节点、被忽略的缺口、采纳后的节点）；
3. **画布内搜索**（`SearchPopover`）传的是画布节点 id，却同样进了目标 id 的解析流程，永远解析为 null——搜索定位因此一直是坏的。

**修复**（`src/lib/locate.ts` + `App.svelte`）：

- 新增 `locateInMap()`，解析顺序：**画布 id 直接命中** → 幽灵 → match → **按标题回退**（NFKC 归一化、大小写不敏感）→ null；
- 按标题回退让「未对比 / 已采纳 / 模板初稿」都能定位到画布上同名节点；
- 仍然找不到时弹出提示「画布上没有对应节点：先做一次对比，或先在画布中创建它。」，不再静默失败；
- 搜索弹窗的画布 id 走直通分支，搜索定位恢复。

**回归**：`tests/e2e/locate.spec.ts`
- 已对比：点击匹配节点选中画布节点；点击缺口选中幽灵节点；
- 未对比：按标题定位到 `HTML`；
- 找不到时出现提示；
- 搜索弹窗结果可定位（此前必失败）。

单测补充：`findNodeByTopic` 的归一化匹配、`locateInMap` 的幽灵优先/标题回退/直通/未命中。

## 24. 测试会话与掌握状态（v0.4 阶段 2/3）

**做了什么**

- **会话**：`workspace.session` 即「附属在目标工作区下的临时工作区」——不进切换列表，带开始时的**目标快照**（会话期间目标冻结）。
