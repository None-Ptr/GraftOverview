# 模板包规范 / Template pack spec

> 社区模板包让任何人把自己整理的目标体系分享给别人。本文件定义格式、校验规则、质量门槛和贡献流程。导入器只信任通过校验的内容。

## 1. 文件格式

- 扩展名：`.json`（建议文件名 `<pack-name>.graftpack.json`）。
- 顶层结构（UTF-8、JSON、无 BOM）：

```json
{
  "format": "GraftOverviewTemplatePack",
  "version": 1,
  "name": "前端进阶包",
  "description": "面向中级前端的补全路线",
  "author": "your-name-or-handle",
  "license": "CC-BY-4.0",
  "locale": "zh",
  "templates": [
    {
      "id": "frontend-advanced",
      "title": "前端进阶",
      "description": "构建、性能与工程化",
      "outline": "- 前端进阶 :: 能独立负责一个模块\n  - 工程化 :: 构建与发布\n    - 构建工具 :: Vite 生产构建\n    - 测试 :: 单元与组件测试"
    }
  ]
}
```

## 2. 字段规则

| 字段 | 必填 | 规则 |
|---|---|---|
| `format` | 是 | 必须为 `GraftOverviewTemplatePack` |
| `version` | 是 | 必须为 `1`；更高版本会被拒绝（不静默升级） |
| `name` | 是 | 1–80 字符，全局唯一（同名包导入会覆盖旧包） |
| `description` | 否 | ≤ 400 字符 |
| `author` | 否 | ≤ 80 字符；不要填个人隐私（邮箱、电话、住址） |
| `license` | 是 | SPDX 标识符，例如 `CC-BY-4.0`、`CC0-1.0`、`MIT` |
| `locale` | 否 | `zh` 或 `en`，默认 `zh` |
| `templates` | 是 | 1–50 个模板 |
| `templates[].id` | 是 | `^[a-z0-9][a-z0-9-]{0,63}$`，包内唯一；导入后会以 `包slug::id` 命名空间化 |
| `templates[].title` | 是 | 1–60 字符 |
| `templates[].description` | 否 | ≤ 200 字符 |
| `templates[].outline` | 是 | 大纲文本，见 §3 |

## 3. 大纲语法

- 每行一个节点：`- 主题 :: 可选说明`（`::` 后为 note，≤200 字，可省略）。
- 缩进必须是 **2 个空格的倍数**；第一行是根节点。
- 允许多个根节点：导入器会自动包一层「标题」根。
- 空标题、奇数缩进、超过上限都会导致整包被拒绝。

节点数量与层级（硬限制）：

| 项 | 限制 |
|---|---|
| 单模板节点数 | 10–200 |
| 单模板层级 | ≤ 5 层 |
| 单模板根节点 | 必须有 `topic` |

## 4. 质量门槛（评审会逐条看）

1. **内容真实**：写你实际掌握或系统整理的体系；不要堆砌关键词。
2. **结构合理**：3–4 层为主，分支按重要性分配，不要平均主义。
3. **每个节点有 note**：用 20–40 字说明「学到什么程度」，比标题更有用。
4. **链接克制**：如给链接，只放官方文档或公认经典资源；**不确定就不要放**，禁止编造 URL。
5. **语言一致**：`locale` 与实际内容一致；中英混排时术语保持统一。
6. **不写营销话术**：不出现「最新」「最强」「包就业」「月薪 X」等承诺。
7. **无个人信息 / 无密钥**：不要包含真实姓名以外的隐私、API Key、公司内部资料。
8. **可复现**：同一份大纲导入后应得到稳定的结构。

## 5. 校验与错误

导入时逐项校验；任何一项失败都会拒绝整包，并给出原因（文件位置）：

- 不是合法 JSON / `format` 不对 → 「不是有效的模板包文件」
- `version > 1` → 「由更新版本创建」
- 缺少 `license` → 「缺少许可证字段」
- 模板数 0 或 > 50 → 「至少一个 / 最多 50 个」
- `id` 非法或重复 → 指出具体 id
- 大纲无效 / 节点过少 / 过多 / 过深 → 指出具体模板名

导入成功后，模板出现在「选择目标体系」的 **社区模板** 区域；选中即可设为目标。若画布为空，还会自动生成一份初稿（删掉不会的即可）。

## 6. 导出模板包

两种方式：

- **导出当前目标为模板包**：把当前工作区的目标体系导出成单模板包（导出对话框）。
- **导出内置模板包**：把 8 套内置模板整体导出，作为贡献起点（导出对话框）。

两种导出都使用本规范格式，可直接作为社区模板包提交。

## 7. 许可与署名

- 你必须拥有所提交内容的权利，或内容本身允许再分发。
- `license` 必须明确；推荐 `CC-BY-4.0`（署名分享）或 `CC0-1.0`（公有领域）。
- 社区模板包默认不再单独署名到界面（`author` 字段仅作记录）；如需署名请在 `description` 中说明。

## 8. 贡献流程

1. 用「导出内置模板包」或「导出当前目标为模板包」得到基线文件。
2. 按 §3/§4 修改；本地用「导入模板包」自测通过。
3. 提交 issue 或 PR，附上 `.graftpack.json` 与一句话说明（面向谁、解决什么）。
4. 维护者按 §4 质量门槛评审；通过后并入内置模板或发布为社区包。

## 9. 版本与兼容

- 模板包 `version` 与应用的 `Workspace` schema 相互独立。
- 未来若升级模板包格式，会提升 `version`；旧版本应用会明确拒绝并提示升级，不静默转换。
- 同 `name` 的包重复导入会**替换**旧包，不会产生重复条目。
